# README 示例与 LED 搜索耗时校准

**不能把 README 的 7ms 与 LED 的约27ms直接比较并判断退化。** 本次在同一台
i5-13500HX 上，使用同一份不可变原版匹配器、OpenCV 1线程 / OpenMP 4线程，
交错测试当前仓库 case1 与8张LED图。原版 case1 搜索中位数为 **2.568ms**；
原版 LED 的8张图搜索中位数平均为 **34.535ms**。差异在原版上已经存在。

## 实际测试条件

| 条件 | 当前仓库 case1 | LED |
| --- | --- | --- |
| 模板数 | 361，包含0°与360° | 900 |
| 金字塔层数 / 步长 | 2层 / `{4,8}` | 3层 / `{4,8,8}` |
| 每层特征点 | 131、71 | 236、111、46 |
| 阈值 | 90 | 75 |
| 图像 | 彩色，1088×960 | 灰度，896×704 |
| 原始输入与边缘处理 | 600×473，四周补250，再裁至16倍数 | 768×576，四周补64 |

case1 直接加载现有 YAML，输入处理复刻 `test.cpp`；LED 沿用正式基准的
SMD导入、900姿态和输入处理。没有调整阈值、减少模板或修改原版算法。
**当前 case1 输入是1088×960，并非 README 历史声称的1024×1024；本次不能称为
精确复现历史7ms。** 历史机器、编译器和线程设置也未确定。

LED 模板更多、精修层数更多、较细层特征点更多，阈值也不同；阈值及画面会影响
进入精修的候选量。因此搜索工作量不能只按模板个数线性换算。此处没有细分
profiling，不能把耗时差定量归因于某一个内部步骤。

## 校准结果

9组输入每组先预热2次，再测15次；轮换起点并逐轮反转顺序，共153次原版调用。
下表为每张图15次正式调用的中位数，单位ms；LED汇总为8张图中位数的等权平均。

| 输入 | 响应图构建 | 搜索 | 外部完整调用 |
| --- | ---: | ---: | ---: |
| case1 | 26.504 | 2.568 | 30.715 |
| LED1 | 14.616 | 30.656 | 46.495 |
| LED2 | 15.256 | 30.652 | 48.489 |
| LED3 | 15.836 | 30.626 | 48.564 |
| LED4 | 15.374 | 32.754 | 47.375 |
| LED5 | 15.401 | 36.733 | 55.822 |
| LED6 | 15.720 | 45.881 | 65.383 |
| LED7 | 15.224 | 33.307 | 49.724 |
| LED8 | 15.172 | 35.669 | 52.722 |
| LED等权平均 | 15.325 | 34.535 | 51.822 |

case1 搜索15次样本范围为 **1.652～5.579ms**；LED8张图的搜索中位数范围为
**30.626～45.881ms**。两者范围统计口径不同，不能混用。各阶段独立取中位数，
因此表中的中位数不一定满足逐项相加。

此前 V4 正式基准在相同LED任务中，原版搜索为 **27.026ms**，V4为 **27.219ms**，
差约0.7%；V4主要将构建阶段从14.794ms降至9.677ms。本次交错校准中原版LED
搜索约34.535ms，较此前原版更慢；这属于不同运行和混合工作负载的观察值，
并不能证明核心回归，也不能据此精确解释缓存、调度或频率的贡献。

计时仅包住匹配调用，不含图片读取、补边、模板导入、CSV输出。原版内部两段
计时来自其日志；外部完整调用还包含适配器日志捕获、返回结果转换和原版缓冲
释放，故大于两段之和。校准目的为消除“历史7ms等于LED900模板任务”的误解，
不作为下一轮优化的性能对照。

## 复现与数据

- 程序：`calibration.cpp`；构建/运行：`run_calibration.ps1 -Run`。
- 原始数据与配置：`calibration_run/raw.csv`、`config.json`、`environment.json`。
- 汇总：`calibration_run/summary.csv`、`summary.json`。
- 统计脚本：`summarize_calibration.py`，检查153调用及每组15正式样本。
- 编译参数：C++14、`-O3 -mssse3 -msse4.1 -fopenmp`。

运行使用已编译程序。环境文件在运行结束后立即保存当前来源/输入和可执行文件
SHA-256，并明确标记该采集时间；未改动核心代码。
