# LED SMD 轮廓匹配效果验证

2026-10-21。本次实验使用 `LED/ku.smd` 内已有的轮廓点，没有从测试图片重新提取模板。调用的是仓库原有 `line2Dup.cpp`，实验入口位于本目录，不改原项目入口。

打开 `overview.png` 查看8张图的结果和局部放大。绿色为匹配模板轮廓，黄色为模板区域及中心。`smd_contours.png` 为从原 SMD 恢复的轮廓在其内嵌模板图上的叠加。该模板描述中央两个黑色电极的边缘，不是 LED 最外圈。

## 结果

8张768×576图片均得到相似度超过75的匹配。最高匹配得分为86.0–98.4，目视落在中央电极附近。SMD内嵌模板与1.bmp的(x=389,y=225,w=184,h=184)区域逐像素相同，所以1.bmp属于模板来源样本；另外7张也都匹配到了目标，得分86.0–91.9。分数是算法相似度，不是识别概率；没有独立标注及负样本，不能据此给出通用准确率或误检率。轮廓对称性和无符号梯度可能造成方向歧义，角度不能直接作为绝对方向测量结果。

| 图片 | 相似度 | 角度（°） | 比例 | 匹配耗时（ms） |

| 1.bmp | 98.4 | 0 | 1.00 | 52.7 |
| 2.bmp | 87.7 | 356 | 1.00 | 53.2 |

Intel Core i5-13500HX，GCC 15.1 `-O3`，SSE4，OpenMP 4线程，OpenCV 4.12设为1线程。每图重复5次，表中为各图中位数；这些中位数平均为64.0ms，折算约15.6 FPS。时间覆盖整个 `detector.match`（响应图、模板匹配、排序和内部日志），不包含读图、生成模板、补边、绘图和保存。原图加64像素边框，实际匹配输入896×704。

搜索配置：360°范围、2°步长，比例0.90/0.95/1.00/1.05/1.10，共900个姿态模板；使用原SMD前两层236/111点，金字塔步幅为4/8。每图展示得分最高的一个姿态；CSV的`candidates`是未经NMS的姿态候选数，不是LED数量。

## SMD读取范围

这是针对所提供 `ku.smd` 的一次性解码实验，不承诺读取其他版本的SMD。读取前校验文件长度、图像/模型版本、4层尺寸、点坐标范围和最终文件偏移。

- 文件标识 `SMD\0`，总长74552字节；内嵌184×184灰度图及同尺寸掩码。
- 模型有4层，尺寸120/60/30/15，轮廓点数量236/111/46/22；每点含标志、浮点x/y和角度。标志原样导出，不解释其未验证的其他含义。
- 基础轮廓点加(32,32)后与内嵌图中两电极边缘吻合。角度转到图像坐标需取负，已用内嵌图梯度方向作核对。
- `smd_contours.csv` 保留所有4层的点；匹配器使用前两层，转换为项目8方向标签。浮点坐标按项目要求取整。

## 复现

在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File artifacts/led_match/run.ps1
```

脚本使用本机已安装的 `F:\mysys2\ucrt64` 编译器、`D:\opencv-4.12.0` 和 Python 3.10/Pillow；不安装依赖。重新运行会覆盖本目录的实验结果。`results.csv` / `summary.json` 保存结构化数据，`run.log` 保存每次匹配的日志。
