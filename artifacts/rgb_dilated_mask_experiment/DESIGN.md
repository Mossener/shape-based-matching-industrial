# RGB official-mask dilation experiment

This is a bounded, source-only successor of the V27 experiment. The authorized
algorithm factor is one exact line in the private V11 snapshot:

```cpp
// RGB control
        erode(mask, local_mask, Mat(), Point(-1, -1), 1, BORDER_REPLICATE);
// treatment
        dilate(mask, local_mask, Mat(), Point(-1, -1), 1, BORDER_REPLICATE);
```

The operation runs inside `ColorGradientPyramid::extractTemplate` at each
actual layer, after the existing mask pyramid construction. It is not an
external mask resize, a ring, or a change to `pyrDown`. All remaining core
bytes, all 22 other private files and the official RGB helper remain exact.
The helper's original `addTemplate(warped,classId,warped_mask)` defines the
control interface. The treatment adapter forwards the original grayscale RGB
warp and original nonempty official warped mask without copying either.
Restoring this interface from V27's empty-mask adapter is necessary to compare
against RGB control; empty-mask selection is not part of this treatment.

The hypothesis is that one-pixel dilation at each layer admits useful object
boundary features excluded by erosion while retaining a constrained region.
Neither the V28 raw-gap diagnosis nor this source preparation proves that
hypothesis or identifies background gradients as the cause of prior losses.
The retained tight crop, black affine border and linear RGB interpolation can
still create artificial boundaries. No result-dependent adjustment is allowed.

All six objects `[1,2,5,8,12,17]`, 72 views each, four scales
`[0.75,1.0,1.5,2.0]` and 12 angles `0..330` by 30 are fixed: 20,736 attempts.
Every success and failure remains; successful IDs are arm-local and dense.
Requested feature targets 32/16 are not limits on actual counts. Two actual
layers, origins, extents, coordinates and original official-mask geometry are
retained. The only instrumentation repair moves the mask snapshot before the
extractor call so an accidental input-mask mutation can actually be detected.

The fixed pre-image gate uses the complete RGB+treatment union at 848x832,
source 720x540, padding `[64,64,64,228]` and alignment 16. An oversized bank
stops the experiment. It cannot enlarge padding, drop a template or filter a
feature. Training exceptions, zero-success objects and missing/duplicate poses
also stop progression while preserving partial evidence.

Quality uses all 400 development frames for each object, both fallback and
fused paths, score/post threshold 85, NMS IoU 0.3, GT IoU 0.5 and eligibility
visibility 0.5. The fixed decision is `TP >= 215 AND FP < 42112`. Report every
object, scene, negative frame and historical identity group, including both
the V22 historical groups and the V27 retained/lost/gained/neither groups.
Groups describe results; no group can choose parameters or trigger fallback.
Independent numeric audit must rederive raw ordering, score bits, NMS, GT
assignment and identity statistics before an accuracy claim. Timing follows
independent quality audit and has its own grant and fixed schedule.

This preparation may read source and JSON declarations only. It may not build,
execute native code, decode an image, open a bank/raw archive, or read private
magnet/SMD. Heldout scenes `[11,14,15,16,17,18,19,20]` and objects 25/29 remain
sealed. Existing bank/image hashes are inherited declarations, not fresh byte
verification. Fresh native receipts must be generated by future granted runs;
historical execution outputs are never copied into this experiment.

The production revision remains `b25df46f6ddf9c24fb43f5836f1414dc38c8caed`.
This experiment cannot promote a production default or establish industrial
generalization from development data.
