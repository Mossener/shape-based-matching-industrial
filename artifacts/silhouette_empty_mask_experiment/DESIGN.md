# Binary source with an empty feature-selection mask

Status: independent successor design for root review. No implementation, template extraction, dataset-image access or native execution has started in this directory. The completed source-only experiment and its immutable evidence remain separate.

The previous fixed recipe attempted 20,736 binary-source templates with the original official feature mask. All six objects had zero successful templates. Its independent numeric audit verified the attempt counts, pose geometry and failure records. This result motivates a different mask policy; it does not authorize changing feature thresholds, feature count, selector, views or pose grid.

The successor changes one algorithmic factor relative to that source-only recipe: pass `cv::Mat()` as the feature-selection mask in `addTemplate`. The training source remains a clone of the same binary official warped mask. The official mask is retained unchanged for the binary source, silhouette box and pose metadata. No dilation, erosion adjustment, threshold sweep, contour injection, mixed bank, object-specific setting or successful-pose selection is introduced.

The fixed V11 extractor erodes a nonempty feature mask before accepting candidates, while an empty mask allows the existing gradient/NMS/scattered selector to consider the valid canvas interior. The source-side blur, Sobel, quantized orientation rules and pyramid remain identical. At L1 the source is naturally smoothed/downsampled, so binary validation applies to the original and warped official mask at L0, not an invented binary requirement on the downsampled source. An empty feature mask stays empty through the pyramid.

Train exactly all 72 official views for each object 1, 2, 5, 8, 12 and 17; scales .75/1/1.5/2; angles 0..330 at 30-degree increments; requested features 32/16; T 4/8; weak/strong 20/40; border 16; unchanged mask ROI, canvas, affine and nearest-neighbor mask warp. Record all 3,456 attempts per object, actual feature counts, failure reason, dense successful IDs and pose mapping. Every pose's source crop, canvas and official warped box must match the frozen original RGB/source-only attempts. The numeric training comparison to source-only concerns feasibility and extracted features only. It cannot produce an image-level accuracy value for the nonexistent source-only bank.

Record actual `tl_x/tl_y`, feature extents and minimum selected-feature distance to the training-canvas edge at each layer. These diagnostics do not trim templates or select a border. Features can lie outside the official silhouette because the blurred boundary has support on both sides. V11 crop offsets then change. Keep the original-image official box conversion `match - pad + warped_official_box_origin - actual_template_tl`, retaining the official width/height; never substitute the feature box or another arm's `tl`. Cross-arm pose association uses object/view/angle/scale, not numerical template IDs.

All matching code must be actual private V11 Git bytes: seven core files and sixteen MIPP files. The successor owns a separate private snapshot and fixed helper copies; relative includes and the compiled translation unit point to those copies. It may copy unchanged source/clone/input/build helpers from the prior experiment only after verifying their frozen SHA, and every successor modification is separately source-pinned. Actual build/runner gates retain compiler tools, import libraries, two-TU GCC dependencies with alias multiplicity, executable and resolved non-system static PE imports. Preserve the stated boundary that this is local provenance and not every OS/plugin resource. Native training is authorized only after root review and coordinated CPU scheduling.

Before any development decode, freeze all six new banks, metadata, attempts and source/build/input pins. Zero successes for any object, any extraction exception, missing pose, geometry mismatch or resource failure makes the complete comparison incomplete. Continue fixed training attempts to preserve evidence where feasible, but never omit a failed object or manufacture valid image negatives. The existing source-only zero banks are unavailable for quality comparison.

If training is feasible, the quality comparison is **new binary-empty-feature-mask detector versus frozen RGB detector**, both freshly evaluated at one shared full-bank padding across both arms and all six objects. Relative to RGB this changes training source and selection-mask policy together, so a quality difference cannot be attributed solely to the mask policy. The prior source-only result independently supplies training-feasibility evidence for that factor. Historical RGB image metrics at old padding are context, not the causal A/B baseline for a different padding.

The one common size is derived from every loaded layer in all twelve banks before development decoding: left/top 64, source 720x540, minimum 848x672, alignment 16; refined L0 requires declared extent plus 64; coarse L1 requires twice the maximum of declared extent and actual maximum coordinate plus one. Do not filter a large template to satisfy a limit. Freeze the geometry CSV, bank metadata and common-padding manifest first. This is a geometric validity condition, not proof of physical SIMD tail safety or recognition improvement.
