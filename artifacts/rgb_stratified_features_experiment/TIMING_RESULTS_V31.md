# V31 三臂配对计时结果

固定开发帧上的独立计时审计通过。主实验 B 相对 C0 的成对完整调用耗时比中位数为
**0.809204（fallback）和 0.831725（fused）**，对应耗时下降约 19.08% 和 16.83%。
这伴随[质量实验](QUALITY_RESULTS_V31.md)中 TP 从 215 降至 187、召回下降 7 个百分点；
准确率门槛失败，**不推广为生产默认**。对象 1 和部分尾部耗时变慢，不能声称普遍加速。

## 固定范围和计时口径

- Windows / i5-13500HX / GCC 15.1 / OpenCV 4.12，CV1 / OMP4；共同画布 848×848。
- 六对象 `[1,2,5,8,12,17]`，固定 64 张开发图，共 384 个对象/图像组合。
- C0、P、B 各运行 fallback/fused；每组合 1 轮预热、12 轮正式。实际 29,952 次调用，
  27,648 个正式样本，每变体 4,608 个；成对记录也为 27,648 条。
- 调用顺序固定为 `(order + frame_ordinal + round) % 6`；每变体每帧在各位置出现两次正式调用。
- `match_ms` 用时钟包围 `Detector::match`，包含其预处理、搜索及结果生成；`external_call_ms`
  还包含本次输入补边、结果转换和后处理。图像解码、bank/metadata 加载、CSV 写出以及随后
  raw 对照均不在这一时钟内。此处“完整调用”不表示从磁盘取图到业务返回的整条产线延迟。
- 每次计时调用均与本臂、本路径已审计的完整 development raw 作精确对照。
  计时输出只保存精确比较结果和计数，没有另存每次计时调用的全 raw。

独立审计核对全部行、轮次、顺序平衡、bank 数量、各臂自己的 raw/selected 参考绑定以及
所有统计量；审计本身不解码图像、不调用 matcher，也不重开每份 raw gzip。
计时运行虽对每次完整 raw 作比较，但没有保存每次 raw，因此不能从 CSV 独立重建每次输出。
复用工作区的固定开发帧不能证明冷启动、现场节拍或留出泛化；本轮不读取封存集。
模板采样还改变了成功模板数和候选分布，当前输出不能把速度变化单独归因为某一个内核。
