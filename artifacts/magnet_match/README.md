# 磁片 SMD 结构与首轮匹配验证

这是针对用户提供的 `磁片/moban.smd` 与 `M01.bmp`～`M07.bmp` 的独立实验，
只增加实验适配器，不修改匹配器核心，也不覆盖 LED 历史实验。

## 格式与安全范围

`moban.smd` 为 652,672 字节，SHA-256 为
`6335f11e6b3c806bbd2e0b4fd2ab5150c015d3e9d18908b78ef6e316aeb06166`。
标识为 `SMD\0`；两幅 640×480 单通道图的版本均为 20161201，模型版本为20171201。
第一幅内嵌图与 **M01 全部307,200个灰度像素完全相同**，所以 M01 仅为模板来源自检，
不能计作独立测试。M02～M07 与来源图不同。

| 项目 | 磁片 | 已有 LED |
| --- | --- | --- |
| 文件字节 | 652,672 | 74,552 |
| 图像尺寸 | 640×480 | 184×184 |
| 头部 ROI xyxy | 121,108,535,383 | 32,32,152,152 |
| 模型起点 | 614468 | 67780 |
| 层数 | 6 | 4 |
| 每层宽高 | 414×275,207×137,104×69,52×35,25×18,13×9 | 120×120,60×60,30×30,15×15 |
| 每层点数 | 1214,605,301,149,73,35 | 236,111,46,22 |

各层宽高直接读取、校验实际 header，不能用重复整数右移替代。每点为小端
`uint32 flag,float x,float y,float angle`。最高两层存在约−0.29的浮点x；
只对这个已经核实的样本允许半像素外延。坐标保留为浮点做旋转/尺度变换后按
项目规则取整，再统一平移到非负的模板裁剪坐标，不用原始浮点坐标直接索引图像。
解析器检查长度、版本、图像块尺寸、每层 header/点数、finite、范围和最终EOF。
Python入口还核对整个文件 SHA，故本实验不是通用 SMD 格式读取器。

第二幅图是二值字节图，只有7654个非零像素，位于磁片内部两个区域；
其具体语义未证实，**不把非零区域当作包含式训练 mask**。实验直接使用保存的轮廓。
模型中其他 header 字段和 flag 的更完整语义仍未知，原值记录在 manifest/CSV 中。

`inspect_smd.py` 独立以 Gaussian(radius=1) 后的 Sobel 梯度核对第一层全部1214点，
图像梯度对负 SMD 角的圆周误差中位为1.07°，p90为2.89°；正号为125.43°/178.48°。
因此导入采用 `theta=(-stored_angle-pose_angle) mod360`，再量化成项目模180°的八类方向。
此核对验证坐标/方向解释，没有验证其他软件全部SMD参数语义。

## 固定首轮配置与结果

`run_20261021_initial` 保留全部21次调用及叠加图。事先固定阈值75、2°角步长、
尺度0.90/0.95/1/1.05/1.10，每配置900姿态，分别试2/3/4层，T为4/8/...，
CV1/OMP4，当前默认优化开关。所有配置采用同一768×640补边输入。
每图仅一次、没有预热，时间只是诊断值，不能当配对性能或稳定节拍。

| 图片 | 角色 | 两层最高分 | 三层最高分 | 四层 |
| --- | --- | ---: | ---: | --- |
| M01 | 来源自检 | 99.75 | 99.86 | 无≥75结果 |
| M02 | 非来源图 | 99.22 | 99.22 | 无≥75结果 |
| M03 | 非来源图 | 99.07 | 99.01 | 无≥75结果 |
| M04 | 非来源图 | 无≥75结果 | 无≥75结果 | 无≥75结果 |
| M05 | 非来源图 | 无≥75结果 | 无≥75结果 | 无≥75结果 |
| M06 | 非来源图 | 无≥75结果 | 无≥75结果 | 无≥75结果 |
| M07 | 非来源图 | 82.21 | 89.70 | 无≥75结果 |

M02/M03/M07的最高姿态分别为234°/1.0、140°/1.0、82°/0.9；
三层叠加目视落在外轮廓和中心孔附近。没有位置、角度、尺度真值，也没有负样本，
“三张有候选”不等同于经标注的召回率，分数不是概率。M04～M06失败可能与
尺度覆盖或粗层筛选等有关，首轮未通过修改参数掩盖失败。四层连来源图也失败，
后续最小诊断确认是补边约束，见下一节；不能用空结果的低耗时声称有效加速。

输出 `results.csv` 包含每配置全部7图的状态、分数、角度、尺度、中心、模板ROI
旋转四角、其轴对齐外接框、候选数及内部阶段时间。框由模板ROI变换得到，
不是独立GT，也不是轮廓的最小外接框。`provenance.json` 保存源码、全部输入
和可执行文件SHA、编译参数、Git版本以及执行前后稳定性校验。

## 最小因果诊断

`run_20261021_diagnostic` 只有四个事先明确的诊断调用，仍使用阈值75：

| 检查 | 结果 |
| --- | --- |
| M01，四层，单姿态0°/1.0，补边64 | 无结果 |
| M01，四层，同姿态，补边256 | 99.8559分 |
| M04，三层，固定尺度0.7、2°全角，补边128 | 99.4852分，312° |
| M06，三层，固定尺度1.25、2°全角，补边128 | 98.7232分，178° |

四层原补边下，精修层l=2输入192×160、模板99×64、border=64，
允许中心区间的上界为x=29/y=32，小于下界64；两边clamp不存在可行中心。
增大补边后同一模板恢复，不需要改核心或重新提取轮廓。`template_geometry.csv`
记录每层裁剪原点、宽高、点数与区间。M04/M06的尺度诊断也恢复了匹配；
这些尺度是算法试验输入，不是独立测量的尺度GT。

## 连续尺度覆盖与粗定位回归

随后固定统一尺度 **0.60～1.40，步长0.05**，保留2°全角、三层、阈值75，
共3060姿态，重新匹配全部7图。此规则不按单张图挑选尺度。全bank逐姿态、
逐精修层检查共6120项；要求完整输入尺寸至少为
`(template_extent+16*T_level)*2^level`。本bank最大需求816×816；
保持左/上128，只增加右/下并按32对齐，实际896×832，右128、下224。
所有区间均可行，详细值在 `padding_preflight.csv` 和 `actual_padding.json`。
固定128不能被推广为任意bank均安全，也没有用同轮重新测所有四层配置。

`manual_boxes.json` 为从原图独立目视标注的外边粗框，精度约±3像素。
计算框采用变换后L0点的连续轴对齐范围，不使用旋转ROI矩形的额外空白。
全部matcher候选保存在 `matcher_candidates.csv`；固定空间NMS抑制IoU>0.3，
再以IoU≥0.5做一对一匹配。独立 `evaluate.py` 用手算实例验证IoU、
严格NMS边界、重复、一对一、空结果和负样例的统计行为。

| --- | ---: | ---: | ---: | ---: | ---: |
| M01 来源自检 | 99.856 | 0° | 1.00 | 0.994 | 3→1 |
| M02 | 99.217 | 234° | 1.00 | 0.975 | 3→1 |
| M03 | 99.012 | 140° | 1.00 | 0.989 | 4→1 |
| M04 开发诊断图 | 99.485 | 312° | 0.70 | 0.965 | 5→1 |
| M05 | 98.250 | 260° | 0.70 | 0.961 | 4→1 |
| M06 | 98.723 | 178° | 1.25 | 0.973 | 2→1 |
| M07 | 89.703 | 82° | 0.90 | 0.972 | 2→1 |

来源自检为TP1/FP0/FN0；6张非来源图粗定位回归为TP6/FP0/FN0。
23条原始姿态候选中16条是同目标的重复假设，NMS后每图一个空间实例。
这些图都已看过首轮结果，属于同组回归，**不是未见留出成绩**。
小规模正样本的上述precision/recall不能推广到通用准确率、负图误检率或工业部署。
中心、角度和模板尺度没有真值，不能据高IoU宣称角度/尺度测量精度。
单次调用也不建立稳定速度结论。

新结果在 `run_20261021_scale_coverage/`，本地打开 `overview.png` 查看全部七图；
原始样本及派生图片没有包含在公开提交中，需用本地样本重新生成。
绿色为SMD轮廓，蓝色为人工粗框，黄色为NMS后点框。原始C++叠加保留在
`L3_M*.bmp.png`；用于审阅的重绘图单独命名，显示两位小数尺度，避免原始诊断标签
一位小数把1.25显示为1.2造成误读，准确数值始终在CSV中。

三个阶段的实际harness源码均冻结在各run的 `source/`，SHA与对应provenance一致；
改进没有覆盖初轮21次失败记录或最小四调用记录。首次两阶段快照只含当时存在的
三个文件，连续覆盖阶段还保存评估器。重放历史阶段应使用其冻结C++源码和
对应配置，不能把当前新增mode误认为初轮程序。

## 复现

```powershell
py -3.10 artifacts/magnet_match/inspect_smd.py
powershell -NoProfile -ExecutionPolicy Bypass -File artifacts/magnet_match/run.ps1 -Run -OutputDirectory artifacts/magnet_match/my_new_run
powershell -NoProfile -ExecutionPolicy Bypass -File artifacts/magnet_match/run.ps1 -Run -Diagnose -OutputDirectory artifacts/magnet_match/my_new_diagnostic
powershell -NoProfile -ExecutionPolicy Bypass -File artifacts/magnet_match/run.ps1 -Run -Validate -OutputDirectory artifacts/magnet_match/my_new_coverage
py -3.10 artifacts/magnet_match/render_review.py artifacts/magnet_match/my_new_coverage
```

输出目录必须为新目录。需要已安装的 Python 3.10、Pillow、numpy、GCC和OpenCV；
默认路径与现有本机实验一致，编译器/OpenCV可通过参数覆盖。链接名仍为opencv_world4120。
脚本把原始文件逐字节复制到被Git忽略的ASCII `build/input`，核对SHA一致后由OpenCV读取，
避免当前Windows OpenCV的中文路径兼容性差异。

结构清单见 `smd_manifest.json`，逐点原值见 `smd_contours.csv`，
`smd_contours.png` 为模板叠加，`input_overview.png` 为7张输入与模板对照。
原始图片与派生图沿用用户样本的权利范围，不额外授予第三方素材许可。

独立核验可运行 `py -3.10 artifacts/magnet_match/audit_validation.py`，
需要本地原始素材及 `inspect_smd.py` 生成的ASCII副本。它重算全部6120条补边约束，
核对输入/源码/冻结副本SHA、SMD结构和来源像素、CSV/JSON一致性，并补充
IoU恰好0.3时不抑制的NMS边界及一对一计数。证据见
[独立审查](INDEPENDENT_REVIEW.md)与 `INDEPENDENT_VALIDATION.json`。
