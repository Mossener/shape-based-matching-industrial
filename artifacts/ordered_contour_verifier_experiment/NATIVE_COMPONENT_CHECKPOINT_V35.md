# V35：原生候选验证、像素入口、场景索引复用与旧版正控

本版推进有序轮廓验证器的可执行实现，并消除验证器逐候选重复建立场景索引的成本。
生产核心继续使用 V11；新验证器尚未完成真实图像质量比较。

## 这次改了什么

- 原生候选适配器连接模板坐标、模板原点、匹配位置、非对称补边和场景轮廓。
  保留完整链、严格整数坐标检查、有理数权重、对应点和诊断数据。
- 像素入口直接使用冻结 V11 的梯度/量化实现，输出完整未扩散方向场。
  模板使用完整官方 mask 与严格平方幅值大于 1600；场景使用原弱阈值标签。
  独立拥有逻辑 ROI，避免父图像边界数据泄漏。
- 新场景缓存一次构建像素成员和链编号两个索引，全部候选共享不可变证据。
  每候选仅查相关成员和链；完整结果和七项求解工作统计保持原样。
- 几何入口复现原 C0 的裁剪、画布、仿射、图像/掩膜插值，并比较模板全部已序列化
  字段及有序特征。没有读取未序列化的 theta。
- 完成完整旧 C0 raw → NMS → 继承 GT 投影的数值连接，供后续实验作正控。

## 场景缓存的速度结果

固定人工场景大小 256×256，包含 1,024 个分离轮廓分量、5,120 个成员行和 2,048 条链。
六轮新旧顺序交替，每轮 256 个候选，计时外完成全部 1,536 个完整结果和 work 比较。
旧版计时调用原函数；计数副本在计时外执行，避免给对照额外计数成本。

- 每轮建立索引对数从 256 降为 1，两个 lookup map 从 512 次构建降为 2 次。
- 含场景准备的旧版总耗时范围 139.256～196.785 ms，缓存版 22.873～33.980 ms。
- 六个逐轮 `缓存总耗时 / 旧版总耗时` 的中位数为 **0.1709649015**；
  此人工负载下对应耗时中位下降约 82.90%。没有按速度比筛选或丢弃轮次。
- 缓存版准备耗时包括新索引建立。索引计数阶段的另一次耗时不混入上述计时。

该负载用于隔离验证重复建表成本；它的模板很小、场景结构人工固定。
不能把这个比例应用到真实图片或 matcher 完整调用，也不据此预测完整 C0 实验耗时。

## 质量目标与下一步

此前 V31 分层方案的 TP/FP/FN 为 187/11,116/213，虽然减少误检，但丢失原 C0
59 个身份，所以不替换默认。新轮廓验证器检查同链、顺序及链内一对一支持，
同样必须接受完整数据验证，不能以合成正确性替代准确率。

下一步重放全部 20,736 次原 C0 训练尝试及 36,398 个已保存层，连接原图到新轮廓证据，
再处理全部 400 场景和 457,279 个候选。固定门槛仍为保留原 215 个 GT 身份、
TP≥215、FP≤21,056；完整接受集合必须重新做 NMS 和 GT 分配。
未满足则保留失败，不根据局部结果更换阈值或忽略难例。
候选池外漏检需要后续单独处理模板覆盖、描述子和候选生成。

本版不包含尚未完成的真实像素/训练重放源与输出；留出场景及对象 25/29 保持封存。
公开选择仅包含明确列出的代码、合成输入/结果、数字证据和报告，
不包含编译产物、真实输入图像/raw/bank/GT 文件或私有磁片/SMD 图及其衍生图。
运行回执保留工作区/工具链绝对路径。编译 Job 的 committed memory 与单进程工作集
分别报告；轮询守护和静态 PE 来源检查保留已有范围限制。
