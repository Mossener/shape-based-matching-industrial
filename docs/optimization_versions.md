# 本地优化版本记录

环境：Windows，i5-13500HX，GCC 15.1，OpenCV 4.12，`-O3 -mssse3 -msse4.1 -fopenmp`。本地 Git 保存源码、测试和数据；可执行文件及构建日志忽略。

## 基线

- `2a91471`：原匹配器、LED/SMD 数据和已有二/三层金字塔实验。
- `9752efa`：保留原始源码的精确字节及参考资料。`artifacts/response_optimization/baseline/manifest.json` 记录 SHA-256。
- 既有配对实验：三层完整匹配 46.5705 ms，响应构建 16.0591 ms。这是历史测量，本次优化采用同进程新基线比较。

## V1：可分离的位或扩散内核

- 新增 `line2Dup_spread.hpp`：把 T×T 次平移 OR 分解为水平和垂直两阶段；保持方向位掩码和零边界语义，SIMD 非对齐访问及标量尾部安全。
- 独立测试：3208 项通过，包含随机位掩码、窄图、T 大于尺寸、非连续 ROI、边界哨兵、缓存复用及别名拒绝。
- 独立微基准，896×704、15 次 warm 中位数：T=4 从 0.2831 降至 0.1489 ms（1.901×）；T=8 从 1.2520 降至 0.3090 ms（4.052×）。比较对象是原 SIMD 实现，非标量代码。
- 本版本提供独立内核和测试；默认匹配流程在后续集成版本启用。局部加速不代表端到端加速。

## V2：融合响应查表与线性内存重排

- 新增 `line2Dup_response.hpp`：预计算 256×8 查表，直接产生八方向的最终线性内存，省去两张半字节图和八张整幅响应中间图。
- 独立测试：127 个用例、1,610,176 次字节比较通过，覆盖全部 256 掩码、随机 LUT、ROI、输出哨兵、复用与尺寸变化。
- 独立微基准，896×704、15 次 warm 中位数：T=4 原 SIMD 响应+重排 2.3780 → 1.3966 ms（1.703×）；T=8 为 2.6520 → 1.4204 ms（1.867×）。本轮所有尺寸的 warm/evicted 组均更快。
- 微基准源码、900 条原始计时、60 组汇总及方法保存在 `artifacts/response_optimization/kernel_bench.cpp`、`kernel_bench/` 与 `kernel_result.md`。合成位掩码内核结果不能代替 LED 完整匹配测试。

## V3：工作区复用与核心集成

- 新增每工作线程独占的 `MatchWorkspace`、三项独立开关 `MatchOptions` 和分段计时。旧接口通过线程局部工作区启用三项优化，关闭逐帧日志。
- 复用每层下采样、模糊、Sobel、幅值乘积、角度、量化、扩散、响应和最终线性内存；每帧重算当前图像、mask 和阈值。修复保留的旧扩散路径在极窄行上的对齐前缀越界。
- 116→27 次灰度、146→57 次彩色 `cv::Mat` 分配/帧（896×704，关闭其他两优化），尺寸变化后正确重建。分配申请字节分别从 39,109,124→516、44,471,292→1,020；这是预处理临时申请统计，不是峰值内存或全部堆分配。
- 五项测试全部通过：内核、1512 次中间矩阵字节对照、五种匹配配置及连续/跨 Detector/并发回归、52 帧分配检查。原版单独编译载入相同 YAML 模板，未重新训练不同模板。
- 单独启用复用的本轮 LED 消融：相对新接口全关闭，构建 15.334→11.526 ms，完整匹配 44.505→38.975 ms。详细运行数据和其他优化的组合结果由 V4 保存。

## V11：扩大公开数据、稳定候选输出与跨线程回归

- 在固定的官方 T-LESS 子集上扩大验证范围：800 张测试图来自 16 个新场景，576 张训练图覆盖 8 个物体；开发场景与场景留出各 400 张，物体 25/29 单独保留作泛化检查。取样在下载和匹配前由 GT、旋转矩阵和固定场景规则确定，没有按匹配难度选图。
- 通过 Range 请求保留 6,100 个原始成员，累计响应体 1,460,279,529 bytes；逐文件 CRC32、SHA-256、尺寸、PNG 尺寸、GT 框/可见比例、训练视角选择和 split 覆盖均通过独立离线审计。外部图像留在忽略的本地缓存，完整 ZIP 和 depth 没有落盘。
- 修复了旧的全局 `sort`/相邻 `unique` 组合：相同 `(class_id,x,y,exact float score)` 现在完整分组，保留最小 template ID，并对最终的 score/template/class/位置优先级给出确定顺序。旧实现会因 OpenMP 合并顺序改变重复候选的保留身份和数量；新契约只改变重复记录的代表和顺序，不重新计算分数或坐标。
- 300 种随机排列的字面量 RED/GREEN 测试、全部 8,191 个合法特征数、1,024 个固定种子的随机累加流和 262,144 个独立标量 patch 位置均通过。25 个输入、475 次跨线程/两种局部路径回归中，400 次当前输出逐字段等于独立 map oracle，75 次冻结 V10/V4 结果 canonical 等价；heldout 图像仍未匹配。
- 新 helper 的完整排序会增加后处理成本，故另行记录相同候选向量的阶段计时：LED 8 图中位后处理约增加 0.004–0.011 ms，T-LESS 开发样本约增加 20.8–56.7 ms，完整 T-LESS API 中位数约为 309.1 ms（冻结 V10 参考约 255.4 ms）。这项正确性修复不是普遍加速，下一轮应先优化确定性去重的算法，再恢复局部中心缓存。
- 限制已经写入独立审查：当前验证未覆盖 cache-on、NaN/非标准浮点、多类真实联合调用的所有组合，也不构成识别准确率或工业节拍保证。详见 `artifacts/match_consolidation/`、`docs/datasets/tless-expanded-acquisition.md` 和 `docs/datasets/tless-expanded-protocol.md`。
