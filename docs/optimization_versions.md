# 本地优化版本记录

环境：Windows，i5-13500HX，GCC 15.1，OpenCV 4.12，`-O3 -mssse3 -msse4.1 -fopenmp`。本地 Git 保存源码、测试和数据；可执行文件及构建日志忽略。

## 基线

- `2a91471`：原匹配器、LED/SMD 数据和已有二/三层金字塔实验。
- `9752efa`：保留原始源码的精确字节及参考资料。`artifacts/response_optimization/baseline/manifest.json` 记录 SHA-256。
- 既有配对实验：三层完整匹配 46.5705 ms，响应构建 16.0591 ms。这是历史测量，本次优化采用同进程新基线比较。

## V1：可分离的位或扩散内核

- 新增 `line2Dup_spread.hpp`：把 T×T 次平移 OR 分解为水平和垂直两阶段；保持方向位掩码和零边界语义，SIMD 非对齐访问及标量尾部安全。
- 独立测试：3208 项通过，包含随机位掩码、窄图、T 大于尺寸、非连续 ROI、边界哨兵、缓存复用及别名拒绝。
- 独立微基准，896×704、15 次 warm 中位数：T=4 从 0.2831 降至 0.1489 ms（1.901×）；T=8 从 1.2520 降至 0.3090 ms（4.052×）。比较对象是原 SIMD 实现，非标量代码。
- 本版本提供独立内核和测试；默认匹配流程在后续集成版本启用。局部加速不代表端到端加速。

## V2：融合响应查表与线性内存重排

- 新增 `line2Dup_response.hpp`：预计算 256×8 查表，直接产生八方向的最终线性内存，省去两张半字节图和八张整幅响应中间图。
- 独立测试：127 个用例、1,610,176 次字节比较通过，覆盖全部 256 掩码、随机 LUT、ROI、输出哨兵、复用与尺寸变化。
- 独立微基准，896×704、15 次 warm 中位数：T=4 原 SIMD 响应+重排 2.3780 → 1.3966 ms（1.703×）；T=8 为 2.6520 → 1.4204 ms（1.867×）。本轮所有尺寸的 warm/evicted 组均更快。
- 微基准源码、900 条原始计时、60 组汇总及方法保存在 `artifacts/response_optimization/kernel_bench.cpp`、`kernel_bench/` 与 `kernel_result.md`。合成位掩码内核结果不能代替 LED 完整匹配测试。
