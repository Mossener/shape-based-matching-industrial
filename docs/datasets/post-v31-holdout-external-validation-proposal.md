## 下一轮最小外部域采集包

先只核对官方目录/GT，验证足够帧数、训练相机/姿态字段与所需 mask 存在。训练视角沿用已冻结的确定性姿态选择规则；测试按排序后帧序列的等分位 rank `floor((k+0.5)N/K)` 取样，算法运行前固定精确 ID。数量或字段不足即停止并记录纯元数据障碍，不按图像难易补样。LM 每序列只标注一个对象实例，先限于已标注实例召回/框定位，不能用其余类别缺 GT 制造负例；完整 precision/负帧率须另证标注覆盖。LM-O 的真负帧数量和覆盖也须先核实，不足就明确不作负帧结论。建模板和评估使用的选定源图最多 896 张，不把派生图加作独立样本；档案内未选图像仍计入全部资源预算。

**来源键与预算。** 使用 `(原始来源族, 原始序列/物理场景, 原始frame ID, 传感器)`，另绑定发布提交和文件哈希；文件夹名不作独立来源。LM scene 2 与 LM-O test 永远同组；共享 PBR、同图裁剪和仿射衍生图随源帧同组。3D 模型可作为已知对象模板的共同先验，单独记录模型哈希，不把它伪装成独立图像来源。LM/LM-O 合并计为 **一个**外部来源族；本轮冻结候选不按外部结果再改。

未来采集拟设响应体累计硬上限 **1,200,000,000 bytes**（含重试），保留文件上限 **2 GiB**，临时档案上限 **512 MiB**：官方 `lmo_train.zip` 355,285,200 bytes、`lmo_test_bop19.zip` 117,550,985 bytes，其余额度用于 LM 测试小子集与 metadata。LM 测试包只允许精确 HTTP 206 Range；拒绝全包降级，预算不足就停止。这是资源上限，未证明子集能在额度内取得，也不是传输量实测。纯数据校验完成后，算法验证仍排队使用单重型槽、当前守护上限及预登记重复次数；无本轮耗时预估。
