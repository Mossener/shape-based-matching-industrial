# 工业轮廓匹配路线图

本文面向公开发布后的持续维护。以下里程碑是计划与验收清单，不代表当前已经具备
工业视觉产品的全部能力。先建立可复现的工程与评估基础，再扩展搜索、定位和部署。
具体精度、召回率、节拍及资源预算，应由目标工件、相机和产线要求确定，本文不预设承诺值。

## 当前具备什么

- 基于梯度方向的离散模板匹配，支持灰度和彩色输入、金字塔搜索，以及训练阶段
  生成旋转和尺度模板。输出包含位置、分数、类别与模板编号；角度、尺度依赖模板元信息。
- 已集成响应构建与搜索优化，并保留独立开关、原调用签名、显式 `MatchWorkspace`
  和分阶段计时。每个并发调用必须独占工作区，匹配期间不得并发修改模板或模态参数。
- 已建立内核逐字节对照、原版/冻结版本的匹配回归、缓冲复用与并发检查，以及可复现
  的原始计时和来源哈希记录。旧签名保留是源码调用兼容，不是二进制 ABI 稳定承诺。
- LED 示例可导入当前 `ku.smd` 样本中已识别的轮廓数据。该工具是**特定样本适配器**，
  不是通用 SMD 格式实现，也没有证明能兼容其他厂商、版本或未提供的文件。

已验证的性能必须按同一轮实验解释。例如，本机 i5-13500HX、GCC 15.1、OpenCV 4.12、
CV1/OMP4、900姿态、三层金字塔、896×704 LED 输入的最近搜索实验中，冻结 V4 的
内部完整调用为38.763ms，搜索三项组合为37.873ms；数据为8张图各自中位数的等权平均。
搜索单项并非都更快，case1 搜索也没有改善，不能外推到任意工件或机器。

上述结果是**运行时间和实现等价性证据**。相同候选集合不等于识别正确；匹配分数也不是
正确概率。当前少量正样本、模板来源图与叠加图不足以建立漏检、误检、定位精度或泛化结论。
离散模板姿态、整数位置和现有候选去重，也不应称为已经完成亚像素精定位或生产级多目标管理。
README 中链接的上游精修分支需要另行评估，不能视为当前分支已经集成的功能。

性能记录见[响应优化报告](../artifacts/response_optimization/README.md)、
[搜索优化报告](../artifacts/search_optimization/README.md)及
[版本记录](optimization_versions.md)。不同运行、输入和计时口径之间不直接相减。

## P0：可移植构建、CI 与接口契约

目标：让维护者和外部贡献者从干净检出得到相同、可解释的行为。

计划工作：

- 将库、示例、正确性测试和基准分别作为构建目标；用 CMake 查找依赖，移除源码内的
  本机路径要求，明确 C++、OpenCV、OpenMP 与 SIMD 支持范围和可选回退路径。
- 为公开声明支持的操作系统、编译器及指令集建立 CI。未进入构建和测试矩阵的平台
  标为未验证；ARM 等平台在具有相应执行环境后再升级支持状态。
- 固化输入格式、尺寸/步长限制、mask、坐标原点、模板裁剪偏移、角度方向、尺度定义、
  分数范围及阈值边界。区分合法空结果、非法输入、空模板库和加载失败。
- 定义模板文件版本、元信息与序列化契约；明确 Detector/Workspace 的所有权、并发和
  参数更新规则。对并列分数的模板身份是否要求确定性，先定义再实现。
- 建立贡献说明、问题模板、变更日志和发布检查；公开使用的数据、模板及来源按文件记录。

验收标准：

- CI 能在声明支持的每个组合上从干净检出构建库、运行无图形界面正确性测试，并安装后
  编译一个独立的最小使用者；开发机绝对路径不是必要条件。
- 运行接口契约测试，覆盖灰度/彩色、非连续 ROI、mask、边界尺寸、空库、非法参数、
  模板读写往返、工作区移动及跨帧/并发使用。异常与空结果符合已发布契约。
- 新贡献可通过文档中的命令完成构建与测试；发布记录关联源码版本和通过的 CI 组合。
  性能基准作为独立作业运行，避免在共享 CI 机器上把耗时波动误判为算法回归。

## P1：ROI、姿态范围、候选管理与 NMS

目标：将原始候选变成可配置、可解释的多目标检测结果，并减少不必要的搜索。

计划工作：

- 设计运行时 ROI 和角度/尺度范围接口，明确与模板 bank、输入 mask、边缘补齐之间的关系，
  保持输出能够映射回原图坐标。搜索范围来自业务先验，不默认缩小。
- 单独统计粗层候选收集、各层精修和最终筛选的耗时、候选数，再决定优化哪个步骤。
- 将候选数限制、分数阈值、最大目标数和 NMS 规则显式配置。区分特征提取时的局部抑制
  与检测结果 NMS，避免把已有特征筛选误当作多目标后处理。
- 明确同类/跨类、相邻零件、重叠目标与对称姿态的保留规则，定义稳定的并列排序策略。

验收标准：

- 全图/完整姿态范围且关闭新增筛选时，回归输出与冻结基线符合既定等价性契约。
- ROI 测试检查原图坐标回映、边缘目标、多个 ROI 与空 ROI；姿态范围测试覆盖跨越角度
  零点、范围端点、尺度端点和对称模板。范围外目标的行为在接口中可见。
- 使用有目标编号的多目标标注验证 NMS，报告重复检测、相邻目标误合并与漏检。
  调整阈值、限候选或范围后同时报告召回变化和耗时，不仅展示更快的结果。
- 达到数量/时间限制时返回可识别的截断状态，不将被截断搜索的结果伪装成完整搜索。

## P2：连续精修、亚像素定位与精度定义

目标：从离散模板的粗定位进入有质量判断的连续位置、角度和尺度估计。

计划工作：

- 在候选之后评估轮廓配准或距离场等精修方案，定义位置、角度、尺度联合优化的输入、
  收敛条件与有效范围。上游 ICP/亚像素分支可作为参考，迁移前验证适用性与维护成本。
- 输出粗定位与精修结果、残差、有效支持点和状态；不收敛、约束越界、低支持度或
  对称性歧义时允许明确拒绝或回退，不能仅返回一个看似精确的小数。
- 明确像素坐标、畸变校正、相机标定和物理单位的边界；毫米精度需要相应标定与测量链。

验收标准：

- 合成连续变换测试使用独立生成的真值，覆盖亚像素平移、非模板角度/尺度、对称形状、
  退化轮廓和初值偏离；报告误差分布、收敛率、失败率及额外耗时。
- 在独立实拍标注和重复拍摄上分别报告位置、角度、尺度误差及重复性，注明标注/测量
  不确定度。重复性不能替代绝对准确度，合成数据也不能替代实物验证。
- 精修开关关闭时保留原流程；开启时对失败回退和不确定姿态有自动化测试。
  精度目标在工件与相机需求确定后填写并作为验收门槛，不沿用上游分支的宣传数值。

## P3：遮挡、杂乱、光照变化的标注验证

目标：让“能匹配样例”转变为可以量化评估的检测能力。

计划工作：

- 建立带版本的数据集与标注规范，包含无目标图、相似干扰件、多个相邻目标，以及不同
  遮挡、背景杂乱、曝光、反光、模糊、尺度和姿态条件。
- 按工件批次、采集时段或场景拆分训练/调参/独立测试集；模板来源及其近重复图不进入
  独立测试，避免同源泄漏。对称工件使用等价姿态或歧义标注规则。
- 建立检测配对与定位容差定义，按条件报告精确率、召回率、每图误检、漏检和定位误差；
  保存失败案例，驱动模板策略、遮挡处理和打分改进。

验收标准：

- 固定数据/标注版本、配置和配对规则的脚本可生成逐图结果与汇总，含分组样本数和
  不确定性说明；空目标图和失败图不得从汇总中消失。
- 测试集在阈值选定后冻结，用未参与调参的数据验收；同时发布阈值曲线和各条件结果，
  不以单一平均分掩盖反光、遮挡等失败子集。
- 每次改变候选裁剪、NMS、精修或模板策略，同时提交准确率回归和性能对照。
  具体通过门槛由应用需求确定；性能提升不能代替识别质量达标。

## P4：工业部署、线程、延迟、内存与失败语义

目标：在约定的设备和输入负载下稳定交付结果，并能区分无目标与系统失败。

计划工作：

- 明确每路图像的工作区归属、Detector 只读共享及模板更新方式；由应用统一配置
  OpenCV/OpenMP 和外层任务并发，避免嵌套过度订阅。
- 分离采集、排队、预处理、搜索、精修、后处理与输出计时；约定丢帧、背压、超时、
  取消和停机行为。若需要时间上限，明确未完成搜索的结果语义。
- 评估首帧、预热、稳态、尺寸切换、模板重载的分配与峰值内存；搜索候选上界和缓存
  保留策略可配置。申请字节统计不等于峰值驻留内存，也不代表零分配。
- 记录输入编号、模型/配置版本、各阶段耗时和失败原因；区分完整搜索无匹配、输入错误、
  模型错误、超时/截断、精修失败和资源故障，便于设备恢复及产线追溯。

验收标准：

- 在指定部署硬件、功耗设置、模板规模及并发相机数下做独立压力/长稳测试，报告首帧、
  median、p95/p99、观测最大延迟、吞吐、队列深度、丢帧及内存曲线；不能只给平均 FPS。
- 线程与资源上限由配置控制；跨帧切换、并发读取和受控模板更新有测试。
  在约定测试时长和负载内，内存保持在协定预算且无持续无界增长。
- 用故障注入验证损坏模型、非法图像、超时、取消和内存压力下的状态、日志与恢复行为。
  空检测不被误报为故障，故障也不被误报为“零件不存在”。
- 完整流程达到应用约定的时延和资源预算后才标记部署通过；普通桌面实测不构成硬实时保证。

## 维护与发布的推进方式

将每个里程碑拆为带输入、预期行为、复现方法和验收条件的 GitHub issue；先完成 P0，
并尽早制定 P3 的数据与标注规范，再推进依赖这些基础的搜索和精修功能。每次发布分别记录
接口变更、正确性/识别质量结果、性能结果和已知限制，并关联可复现的版本与数据。
算法等价性、识别准确率、性能和部署可靠性分别验收，避免用其中一项替代其他项。
